## 1. Empezar por service, porque el frontend va a necesitar endpoints contra los cuales pedir datos (login, registro). Si empezamos por React, estariamos maquetando pantallas que no tienen con que hablar todavia. El orden natural es: primero un servidor que responda algo, aunque sea minimo, y de ahi vamos creciendo.

# 2. Vamos a empezar creando rama de trabajo

git checkout develop
git pull
git checkout -b chore/server-setup (chore porque todavia no es una feature visible para el usuario final, es trabajo de infraestructura/andamiaje)

# 3. Inicializar proyecto de Node dentro de server/

cd server, pnpm init

# 4. Instalar express

pnpm add express

# 5. Instalar nodemon (solo desarrollo)

pnpm add --save-dev nodemon o pnpm add -D nodemon (abreviado)
nodemon reinicia el servidor automaticamente cada vez que se guarda un cambio

# 6. Agregar scripts al package.json creado al iniciar el proy

Es solo para ejecutar comandos
"scripts": {
"dev": "nodemon src/index.js",
"start": "node src/index.js"
}

# 7. Primer archivo (server/src/index.js)

Es para levantar el servidor

# 8. PASOS COMMITEAR - El git ignore debe tener minimo node_modules/ .env

git status
git add . (todo) o server/package.json server/package-lock.json server/src/index.ks (lo que queremos commitear)
git commit -m "comentario"
git push -u origin chore/server-setup

# 9. Abrir Pull Request en Github, agregar descripcion, leer Files changed del PR

Luego de revisar todo bien, hacer un Squash and merge (no Create a merge commit),
porque Squesh colapsa todos los commits de nuestra rama en uno solo al aplicarlos sobre develop (branch), como ahora es un solo commit no se nota la diferencia, pero cuando una rama tenga 5,6 commits tipo "wip", "fix typo", etc, squash deja un historial limpio en develop con un commit por unidad de trabajo.
Luego de mergear, dar a Delete branch en Github.

## 1. Empezar por service, porque el frontend va a necesitar endpoints contra los cuales pedir datos (login, registro). Si empezamos por React, estariamos maquetando pantallas que no tienen con que hablar todavia. El orden natural es: primero un servidor que responda algo, aunque sea minimo, y de ahi vamos creciendo.

# 9. Abrir Pull Request en Github, agregar descripcion, leer Files changed del PR

Luego de revisar todo bien, hacer un Squash and merge (no Create a merge commit),
porque Squash colapsa todos los commits de nuestra rama en uno solo al aplicarlos sobre develop (branch), como ahora es un solo commit no se nota la diferencia, pero cuando una rama tenga 5,6 commits tipo "wip", "fix typo", etc, squash deja un historial limpio en develop con un commit por unidad de trabajo.
Luego de mergear, dar a Delete branch en Github.

git checkout develop
git pull
git branch -d chore/server-setup (rama que habia creado borrar)

###### RECORDATORIO

        # Crear feature
        git checkout develop
        git pull
        git checkout -b feature/auth-login

        # Trabajar
        git add .
        git commit -m "feat: endpoint de login con emisión de access token JWT"

        # Primera subida
        git push -u origin feature/auth-login

        EN GITHUB:
            PR: feature/auth-login → develop
                    ↓
            Review
                    ↓
            Squash and merge
                    ↓
            Delete branch

        LUEGO EN LOCAL PC:
            git checkout develop
            git pull
            git branch -d feature/auth-login
